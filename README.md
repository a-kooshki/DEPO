# DEPO (Electron)

سامانه‌ی مدیریت انبار و فراوری سنگ — از بارگیری کوپ از معدن تا برش، پالت‌بندی و فروش. این پروژه با Electron + React + Vite اجرا می‌شود و می‌توانید از آن فایل نصبی بگیرید.

## گردش کار کلی
`قرارداد` → `حواله` (ورود کوپ از معدن) → `کوپ` (ردیابی وضعیت) → `برش` → `ثبت پالت` (اسلب) → `موجودی و فروش`.
هر مرحله به مرحله‌ی قبل وصل است: حواله به یک قرارداد فعال، فرم برش به یک کوپ ثبت‌شده در حواله، و پالت به همان شماره کوپ (به‌عنوان «کد کوپ») وصل می‌شود.


## پیش‌نیازها
- Node.js نسخه 18 یا بالاتر
- npm

## اجرای پروژه در حالت توسعه
1. وابستگی‌ها را نصب کنید:
   ```bash
   npm install
   ```
2. برنامه را در حالت توسعه اجرا کنید:
   ```bash
   npm run dev
   ```

## ساخت خروجی نهایی (Desktop Build)
1. ابتدا خروجی فرانت ساخته می‌شود:
   ```bash
   npm run build:renderer
   ```
2. برای گرفتن خروجی بدون installer (صرفاً unpacked)، اجرا کنید:
   ```bash
   npm run pack
   ```
3. برای گرفتن فایل نصبی (installer)، اجرا کنید:
   ```bash
   npm run dist
   ```

> خروجی‌ها داخل پوشه `dist/` و `dist_electron/` تولید می‌شوند (بسته به پلتفرم).


## اگر ظاهر برنامه به‌هم ریخته است
این پروژه از کلاس‌های Tailwind استفاده می‌کند. اگر استایل‌ها اعمال نشد:
1. حتماً یک‌بار `npm install` را کامل اجرا کنید.
2. بعد با `npm run dev` اجرا کنید.

## خروجی نصبی روی هر سیستم
- **Windows**: فایل `.exe` (NSIS installer)
- **Linux**: فایل `.AppImage` و `.deb`
- **macOS**: فایل `.dmg`

## دستورات مستقیم برای هر پلتفرم
- ویندوز:
  ```bash
  npm run dist -- --win
  ```
- لینوکس:
  ```bash
  npm run dist -- --linux
  ```
- مک:
  ```bash
  npm run dist -- --mac
  ```

## نکته مهم برای Windows
اگر روی لینوکس یا macOS هستید، ساخت installer ویندوز ممکن است نیاز به Wine/محیط CI مناسب داشته باشد. بهترین حالت این است که installer هر سیستم را روی همان سیستم (native) بسازید.

## شخصی‌سازی آیکن برنامه
اگر خواستید آیکن بگذارید:
1. پوشه `build/` بسازید.
2. آیکن‌ها را قرار دهید:
   - `build/icon.ico` برای Windows
   - `build/icon.icns` برای macOS
   - `build/icon.png` برای Linux

`electron-builder` به‌صورت خودکار از این آیکن‌ها استفاده می‌کند.


## قرارداد
- هر قرارداد شامل شماره، تناژ کل، معدن، نوع سنگ، فرمت کوپ (لاشه/قواره)، قیمت فی هر تن و تعداد کوپ است.
- قیمت فی هر تن به **ریال** است و همه‌جا (فرم ثبت، فهرست قراردادها، جزئیات) با جداکننده‌ی هزارگان نمایش داده می‌شود (مثل ۱٬۲۵۰٬۰۰۰).
- قرارداد تازه‌ثبت‌شده همیشه «فعال» است. از تب «قراردادها» می‌توان آن را غیرفعال/فعال کرد.
- **حواله فقط به قرارداد فعال وصل می‌شود.** اگر قراردادی غیرفعال شود، دیگر در فهرست انتخاب حواله ظاهر نمی‌شود و ثبت حواله‌ی جدید با آن مسدود است (حواله‌های قبلاً ثبت‌شده دست‌نخورده می‌مانند).
- حذف قرارداد در صورتی که حواله‌ای به آن وصل باشد مسدود می‌شود.
- در تب «قراردادها»، کلیک روی هر قرارداد جزئیات را باز می‌کند: مجموع تناژ حواله‌های ثبت‌شده در برابر تناژ کل، تعداد کوپ رسیده در برابر تعداد کوپ قرارداد، درصد پیشرفت هرکدام، و ارزش کل/باقی‌مانده‌ی قرارداد به ریال (تناژ × قیمت فی).

## ثبت حواله و مدیریت حواله‌ها
- انتخاب قرارداد، نام معدن و فرمت کوپ پیش‌فرض ردیف‌های تازه را خودکار پر می‌کند (بدون بازنویسی ردیف‌هایی که کاربر قبلاً پر کرده).
- هر حواله شامل شماره حواله، وزن کل (تن)، نام راننده، **شماره پلاک ماشین (۵ رقم)**، معدن، قرارداد، تاریخ شمسی و فهرست کوپ‌هاست.
- هر کوپ شامل شماره کوپ، **کد مارک کوپ (سه حرف + سه رقم، مثل ABC-123 — یکتا در کل برنامه)**، نوع سنگ، **فرمت (لاشه/قواره)**، **درجه کوپ (یک حرف A تا Z، مستقل از درجه‌ی سنگ بریده‌شده)** و وزن تقریبی است.
- مجموع وزن کوپ‌ها باید دقیقاً با وزن کل حواله برابر باشد؛ تا وقتی برابر نشود دکمه‌ی ثبت غیرفعال است.
- شماره کوپ و کد مارک هر دو باید در کل برنامه یکتا باشند.
- همه‌ی فیلدها با Enter قابل پیمایش‌اند و در انتهای هر ردیف، ردیف تازه ساخته و فوکوس می‌شود.

## کوپ
تب «کوپ» وضعیت هر کوپ را از ورود تا فروش نشان می‌دهد:
- سه شمارنده‌ی بالای صفحه: تعداد کوپ موجود در انبار (هنوز بریده نشده)، تعداد بریده‌شده، و تعداد بریده‌شده‌ی فروخته‌شده — هرکدام کنار تعداد، مجموع وزن (تن) و در دو مورد آخر متراژ مربوطه (m²) را هم نشان می‌دهد.
- برای هر کوپ: شماره حواله، قرارداد، کد مارک، وزن، درجه کوپ، نوع، فرمت، دستگاه برش، ضخامت برش، تعداد/متراژ برش‌شده (از فرم برش)، تعداد/متراژ پالت‌شده، تعداد/متراژ فروخته‌شده (از پالت‌ها)، و درجه‌ی سنگ پس از برش (از ثبت پالت).
- وضعیت هر کوپ یکی از این پنج مرحله است: **در انبار → زیر دستگاه برش → بریده‌شده → به‌صورت اسلب در پالت → فروخته‌شده**. مرحله از روی داده‌های واقعی (وجود فرم برش، پرشدن جدول اسلب، وجود اسلب در پالت، وجود فاکتور) محاسبه می‌شود، نه یک پرچم دستی.
- برای کوپ‌های برش‌خورده، دو نوار درصد نشان می‌دهد چه سهمی از مساحت بریده‌شده تا الان پالت شده و چه سهمی فروخته شده.

## ثبت برش و مدیریت فرم‌های برش
- شماره ردیف از ۱ شروع می‌شود و به‌ترتیب ادامه پیدا می‌کند (حذف یک فرم شماره‌های بعدی را عوض نمی‌کند).
- با وارد کردن شماره کوپ، نوع سنگ، شماره حواله، **فرمت کوپ** و وزن تقریبی در صورت وجود آن کوپ در یک حواله خودکار پر می‌شوند؛ در غیر این صورت به‌صورت دستی وارد می‌شوند.
- **دستگاه برش دیگر آزادانه تایپ نمی‌شود** — از تب «تنظیمات» دستگاه‌ها تعریف می‌شوند و در این فرم از یک فهرست انتخاب می‌شوند. برای هر دستگاه می‌توان یک «تیغه» تجهیز کرد (هم تیغه از تنظیمات تعریف می‌شود)؛ فرم برش هنگام ذخیره، هم نام دستگاه و هم نام تیغه‌ی فعلاً نصب‌شده روی آن را با هم ثبت می‌کند تا بعداً مشخص باشد هر برش با کدام دستگاه و کدام تیغه انجام شده.
- فرم بدون تکمیل جدول اسلب هم قابل ثبت است. دکمه‌ی **«ذخیره و چاپ»** فرم را ابتدا ذخیره می‌کند (با شماره ردیف واقعی و مهرهای زمانی درست) و سپس بلافاصله پنجره‌ی چاپ را باز می‌کند — دیگر پیش‌نمایش بدون ذخیره وجود ندارد.
- اگر طول و عرض برعکس وارد شوند (عدد بزرگ‌تر در فیلد عرض و کوچک‌تر در فیلد طول)، به‌طور خودکار درست می‌شوند: «طول» همیشه بزرگ‌تر از «عرض» ذخیره می‌شود (دقیقاً مثل ثبت پالت). مساحت مستقل از این ترتیب درست محاسبه می‌شود.
- فرمول مساحت هر ردیف: **طول × عرض × تعداد**. (نسخه‌های قبلی در محاسبه‌ی مساحت رکوردهای ذخیره‌شده باگ داشتند که رفع شد.)
- چاپ فرم برش برخلاف بقیه‌ی اسناد (که انگلیسی‌اند) **فارسی و راست‌به‌چپ** است و شامل دستگاه، تیغه و فرمت کوپ (لاشه/قواره) هم می‌شود. اگر کمتر از ۸ ردیف اسلب ثبت شده باشد، ردیف‌های خالی تا ۸ ردیف در چاپ اضافه می‌شود. پایین چاپ یک بخش «ملاحظات» با چند خط خالی هست که فقط روی کاغذ چاپ می‌شود و در برنامه ذخیره یا وارد نمی‌شود.
- **زمان‌بندی برش، دو مرحله‌ی خودکار و دو مرحله‌ی دستی دارد:**
  - «شروع برش» — خودکار، همان لحظه‌ای که دستگاه انتخاب و فرم برای اولین بار ذخیره می‌شود.
  - «ورود به خط فراوری» — خودکار، همان لحظه‌ای که جدول ابعاد (طول/عرض/تعداد) برای اولین بار با محتوای واقعی ذخیره می‌شود.
  - «پایان برش» و «خروج از خط فراوری» — هر دو **دستی**؛ کاربر تاریخ (شمسی) و ساعت را مستقیماً در همین فرم وارد می‌کند.
  - دو مورد خودکار فقط یک‌بار ثبت می‌شوند و در فرم به‌صورت غیرقابل‌ویرایش (فقط‌خواندنی) نمایش داده می‌شوند؛ دو مورد دستی هر بار قابل ویرایش‌اند.

## دستگاه‌ها و تیغه‌ها (تب تنظیمات)
- دستگاه‌های برش کارخانه (مثلاً «دستگاه A»، «دستگاه B») و تیغه‌ها هرکدام در تب «تنظیمات» ثبت می‌شوند.
- هر تیغه را می‌توان به یک دستگاه «تجهیز» کرد؛ تجهیز یک تیغه‌ی تازه به دستگاهی که از قبل تیغه داشته، آن تیغه‌ی قبلی را خودکار از آن دستگاه جدا می‌کند (هر دستگاه در هر لحظه فقط یک تیغه دارد).
- حذف دستگاهی که در فرم‌های برش استفاده شده مسدود است؛ حذف تیغه همیشه آزاد است (سوابق قبلی نام دستگاه/تیغه را همان لحظه‌ی ثبت نگه می‌دارند و با حذف بعدی خراب نمی‌شوند).

## دسترسی موبایل و شبکه‌ی داخلی کارخانه
برنامه هم‌زمان با اجرا، یک سرویس وب سبک روی شبکه‌ی محلی (LAN) کارخانه بالا می‌آورد که فقط دو فرم را ارائه می‌دهد: **ثبت پالت** و **ثبت برش** — بدون چاپ، جستجو یا تنظیمات، چون این‌ها برای کاربر موبایل لازم نیست.
- از تب «تنظیمات»، کارت «اتصال موبایل» آدرس شبکه (و یک QR Code) را نشان می‌دهد. با اسکن آن یا باز کردن آدرس در مرورگر هر گوشی/لپ‌تاپ روی همان Wi-Fi، صفحه‌ی موبایل باز می‌شود.
- کاربر موبایل ابتدا نام خودش را از فهرستی که در تب «تنظیمات → کاربران ثبت موبایل» تعریف شده انتخاب می‌کند (بدون رمز عبور) و این نام روی رکوردهایی که ثبت می‌کند می‌ماند.
- این سرویس **مستقل از باز بودن پنجره‌ی دسکتاپ** کار می‌کند: با بستن پنجره، برنامه در پس‌زمینه (آیکن Tray) فعال می‌ماند و سرویس شبکه قطع نمی‌شود؛ فقط گزینه‌ی «خروج کامل» در منوی Tray سرویس را کاملاً متوقف می‌کند.
- **قابلیت اطمینان هم‌زمانی:** برخلاف روش قدیمی (که کل آرایه‌ی داده جایگزین می‌شد)، پالت و فرم برش از طریق عملیات مشخص (نه جایگزینی کامل) روی یک نسخه‌ی واحد از داده در پردازش اصلی اعمال می‌شوند. یعنی اگر همان لحظه یک نفر از دسکتاپ و نفر دیگری از موبایل ثبت کنند، هیچ‌کدام داده‌ی دیگری را پاک نمی‌کند، و شماره‌ی ردیف فرم برش هم توسط همان پردازش مرکزی تخصیص داده می‌شود تا دو ثبت هم‌زمان یک شماره‌ی تکراری نگیرند.
- هر ثبتی از موبایل، بلافاصله (بدون نیاز به رفرش) در همان پنجره‌ی دسکتاپ هم دیده می‌شود.
- تلاش برای افزودن سنگ به پالتی که قبلاً فروخته شده، چه از دسکتاپ و چه از موبایل، رد می‌شود.

## ثبت پالت
- شماره پالت و مشخصات مشترک (نوع سنگ، کد کوپ، درجه) یک‌بار بالای جدول وارد می‌شوند.
- «کد کوپ» به فهرست کوپ‌های ثبت‌شده در تب «ثبت حواله» وصل است: اگر شماره‌ی واردشده با یک کوپ ثبت‌شده مطابقت داشته باشد، نوع سنگ به‌طور خودکار پر می‌شود. اگر کوپ در هیچ حواله‌ای ثبت نشده باشد، هشدار غیرمسدودکننده نمایش داده می‌شود ولی ثبت همچنان امکان‌پذیر است.
- ردیف‌های خالی همیشه همان مشخصات سربرگ را نشان می‌دهند. هر ردیف در لحظه‌ی تایپ، مشخصات وقت خودش را برمی‌دارد؛ پس تغییر بعدی سربرگ فقط روی ردیف‌های تازه اثر می‌گذارد.
- اگر مشخصات را دیر عوض کردید، دکمه‌ی «به‌روزرسانی» کنار هر ردیف آن ردیف را دوباره به سربرگ وصل می‌کند.
- طول و عرض به سانتی‌متر وارد می‌شوند و با خارج شدن از فیلد به متر تبدیل می‌شوند. تبدیل idempotent است؛ عبور دوباره از فیلد مقدار را خراب نمی‌کند. اگر مقدار طول و عرض جابجا وارد شوند، هنگام ذخیره به‌طور خودکار درست می‌شوند (طول همیشه بزرگ‌تر از عرض ذخیره می‌شود؛ مساحت تغییری نمی‌کند). همین قانون در جدول اسلب فرم برش هم اعمال می‌شود.
- ضخامت هم به سانتی‌متر وارد می‌شود و هنگام ذخیره به متر تبدیل می‌شود.
- فیلد «تعداد» دیگر مقدار پیش‌فرض ۱ ندارد؛ کاربر باید آن را صریحاً وارد کند تا از ثبت سهوی تعداد اشتباه جلوگیری شود.
- با Enter بین فیلدها و در انتهای هر ردیف به ردیف بعدی می‌روید.
- خلاصه‌ی آخرین پالت ثبت‌شده پایین فرم می‌ماند و از همان‌جا قابل چاپ یا ویرایش است.
- «ویرایش پالت» تمام ردیف‌های آن پالت را در فرم باز می‌کند و هنگام ذخیره، ردیف‌های قبلی را جایگزین می‌کند.

## چاپ کارت پالت و گزارش
خروجی کارت پالت، گزارش موجودی، حواله و فرم برش مستقیماً به پنجره‌ی چاپ سیستم فرستاده می‌شود؛ خبری از تولید فایل PDF نیست.
از همان پنجره می‌توانید چاپگر را انتخاب کنید یا «Save as PDF» را بزنید.
- کارت پالت: لوگو و QR دو برابر اندازه‌ی معمول چاپ می‌شوند و ستون درجه در چاپ نمایش داده نمی‌شود (فقط نوع، ضخامت، طول، عرض، تعداد و متراژ). اگر تعداد ردیف‌ها زیاد باشد، جدول به‌صورت خودکار چند صفحه‌ای می‌شود و سربرگ ستون‌ها در هر صفحه تکرار می‌شود.
- گزارش موجودی: هر پالت در یک کادر جدا با سربرگ (شماره پالت، وضعیت، جمع تعداد و متراژ) چاپ می‌شود. کادر هر پالت با قانون «جلوگیری از شکستن داخل کادر» بین دو صفحه پاره نمی‌شود؛ فقط پالتی که به‌تنهایی از یک صفحه بلندتر باشد ناچار به ادامه در صفحه‌ی بعد است. نمایش ستون درجه سنگ در این گزارش از تب «تنظیمات» قابل روشن/خاموش کردن است.

## لوگو و سربرگ چاپ
- لوگوی پیش‌فرض: فایل را با نام `logo.png` در پوشه‌ی `public/` بگذارید و دوباره build بگیرید.
- از تب «تنظیمات» می‌توانید لوگوی سفارشی (حداکثر ۱.۵ مگابایت) آپلود کنید که جایگزین لوگوی پیش‌فرض می‌شود.
- متن سربرگ، نمایش لوگو/QR و اندازه‌ی فونت چاپ از همان تب و برای همه‌ی خروجی‌های چاپی (کارت پالت، گزارش، حواله، فرم برش) قابل تغییر است.

## تاریخ شمسی
تمام فیلدهای تاریخ (حواله، فرم برش، زمان‌های شروع/پایان برش) با تقویم شمسی کار می‌کنند: ورودی و نمایش شمسی است، و مقدار روی دیسک به‌صورت میلادی (ISO) ذخیره می‌شود. تبدیل تقویم به‌صورت داخلی و بدون کتابخانه‌ی خارجی انجام می‌شود (`src/jalali.js`)، پس برنامه به‌طور کامل آفلاین کار می‌کند.

## اطلاعات و پشتیبان‌گیری
- داده‌ها در `stone-inventory-data.json` داخل پوشه‌ی userData سیستم‌عامل ذخیره می‌شوند. مسیر دقیق: منوی «پرونده ← محل ذخیره اطلاعات».
- نوشتن روی فایل اتمیک است: ابتدا یک فایل موقت نوشته و روی دیسک flush می‌شود، سپس جایگزین فایل اصلی می‌شود و نسخه‌ی قبلی به‌عنوان backup نگه داشته می‌شود.
- اگر فایل اصلی خراب باشد، برنامه به‌طور خودکار از backup بازیابی می‌کند و فایل معیوب را کنار می‌گذارد.
- اگر هیچ‌کدام خوانده نشوند، ذخیره‌سازی خودکار **متوقف** می‌شود تا داده‌های موجود با یک فایل خالی بازنویسی نشوند و پیام هشدار نمایش داده می‌شود.
- از منوی «پرونده ← تهیه نسخه پشتیبان» می‌توانید یک کپی از داده‌ها بگیرید.
- ساختار فایل داده با نسخه‌های قبلی سازگار است؛ نیازی به مهاجرت نیست. فیلدهای `waybills`، `cuttingForms`، `contracts`، `machines`، `blades` و `operators` تازه اضافه شده‌اند و در فایل‌های قدیمی به‌صورت آرایه‌ی خالی در نظر گرفته می‌شوند.
- `stones` و `cuttingForms` دیگر با یک ذخیره‌سازی «کل سند» جایگزین نمی‌شوند؛ فقط از طریق عملیات مشخص (افزودن/ویرایش/حذف پالت یا فرم برش) در پردازش اصلی تغییر می‌کنند — همین چیزی است که استفاده‌ی هم‌زمان از دسکتاپ و موبایل را بدون خطر از دست رفتن داده ممکن می‌کند.

## فونت
برنامه در حالت packaged آفلاین اجرا می‌شود و فونت از اینترنت بارگذاری نمی‌شود.
برای استفاده از Vazirmatn در نسخه‌ی نصبی، فایل‌های `.woff2` را در `public/fonts/` بگذارید و یک قاعده‌ی `@font-face` در `src/styles.css` اضافه کنید. در غیر این صورت از فونت سیستم (Segoe UI / Tahoma) استفاده می‌شود.

## ساختار کد

برای توسعه‌پذیری بهتر، shell برنامه و منطق/دادهٔ مشترک در `src/App.jsx` نگه‌داری می‌شود و رابط هر تب در فایل مستقل `src/tabs/` قرار دارد. تب‌ها از `src/app/AppContext.jsx` استفاده می‌کنند؛ به این ترتیب انتقال UI به فایل جدا باعث تغییر رفتار، ذخیره‌سازی یا جریان داده نمی‌شود و از prop drilling جلوگیری می‌شود.

* `src/tabs/EntryTab.jsx`: ثبت پالت
* `src/tabs/InventoryTab.jsx`: موجودی و فروش
* `src/tabs/ContractEntryTab.jsx` و `ContractListTab.jsx`: قراردادها
* `src/tabs/WaybillEntryTab.jsx` و `WaybillListTab.jsx`: حواله‌ها
* `src/tabs/CuttingEntryTab.jsx` و `CuttingListTab.jsx`: فرم‌های برش
* سایر tabهای مستقل: کارت پالت، کوپ، انواع سنگ و تنظیمات
